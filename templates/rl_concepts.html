Reinforcement Learning Concepts

How an agent learns a policy from rewards instead of from labelled examples — the fourth pillar of Machine Learning, and the one that closes the loop on our project.

Reading guide. This page is Part 1 of 2. It explains the theory with the 10×10 grid used in our application as a running example. Part 2, RL Application, lets you train the agent yourself.
# 1. Name and Definition

What is Reinforcement Learning?

Reinforcement Learning (RL) is the area of Machine Learning concerned with how an agent learns to choose actions in an environment in order to maximise a cumulative reward signal. Unlike the supervised models in this project, there are no target labels: the only feedback is a scalar reward, and the system has to discover on its own which behaviour pays off.

The formal definition in terms of the tuple (S, A, P, R, γ):

  • S (States): the set of possible situations the agent can be in.
  • A (Actions): the set of moves available in each state.
  • P (Transition probability): how the environment reacts, P(s'|s,a).
  • R (Reward): the immediate feedback R(s,a,s') for a transition.
  • γ (Discount factor): how much future reward matters, in [0,1].

In our application the agent is a delivery robot on a 10×10 grid. States are cells, actions are Up / Down / Left / Right, transitions are deterministic, and the reward tells the agent whether it moved safely, hit a wall, entered a danger zone or reached the target.

# 2. How It Works

The agent-environment loop

Training is an endless cycle of observe, decide, act, get rewarded. Each pass through the grid is called an episode, and the total reward collected during an episode is the return. The agent's objective is to maximise the expected return, and because rewards are delayed — you only learn that a wall was a mistake after you have bumped into it — it must look several steps ahead.

The agent perceives the environment and receives its state. On our grid this is the coordinate of the cell it currently occupies, for example (4, 7).

A policy maps states to actions. During learning the policy is ε-greedy: with probability ε it acts randomly to explore, otherwise it picks the action with the highest Q-value to exploit what it already knows.

The environment applies the action and answers with a reward and the resulting state. On our grid a valid move gives -1, a blocked move -10, entering a danger zone -15 and reaching the target +100.

The agent revises its estimate of how good that action was, blending the reward it just received with the best value it can expect from where it now stands.

The Bellman optimality update

Q(s,a) ← Q(s,a) + α · [ r + γ · maxa' Q(s',a') − Q(s,a) ]

Q(s,a) is the estimated return of taking action a in state s and then continuing optimally. The bracket is the Temporal Difference error: the gap between what the agent expected and what actually happened. α is the learning rate, controlling how much of that correction is absorbed.

# 3. Problems It Can Solve

Where reinforcement learning applies

Sequential decisions

  • Robotics — walking, grasping, path planning (our grid).
  • Game playing — AlphaGo, chess, Atari.
  • Autonomous driving — lane changes and braking.
  • Resource scheduling — datacentres, supply chains.

Control and optimisation

  • Energy management — HVAC and smart grids.
  • Portfolio trading — adaptive position sizing.
  • Recommendation — long-term user engagement.
  • Telecom — handover and power control.

The distinguishing feature is consequences that unfold over time: an action changes the options available later, so greedy short-term decisions can be globally wrong.

# 4. Main Characteristics

Properties of the problem

  • Learning by trial and error — no labels, only rewards.
  • Delayed feedback — consequences may arrive many steps later.
  • The exploration/exploitation trade-off — the agent must both try new things and cash in what it knows.
  • Sequential and stateful — each decision alters the next.
  • Rewards may conflict — a locally good move can be globally bad.
  • Credit assignment — working out which past action deserves the blame or the credit.
# 5. Types / Variants

Families of reinforcement learning

Model-free agents learn the value function directly from experience, with no knowledge of the transition probabilities. Model-based agents first learn a model of the environment and plan with it. Our application is model-free.

Value-based methods estimate Q(s,a) and act greedily — this is Q-Learning and SARSA. Policy-based methods learn the policy π(a|s) directly, which is what Policy Gradient methods and actor-critic do.

On-policy algorithms, such as SARSA, only learn from the data generated by the current policy. Off-policy algorithms, such as Q-Learning, can learn from data collected by any policy, including exploratory ones.

Tabular methods keep an explicit Q row per state, which is only possible for small finite spaces. When the state space is too large — images, continuous control — the value function is approximated with a neural network or a linear model, exactly as our application approximates it with SGDRegressor.

# 7. Advantages

Strengths

  • Optimises the real objective — it maximises long-term return instead of minimising a proxy error.
  • No labelled data required — rewards are usually far cheaper to obtain than annotations.
  • Discovers non-obvious strategies — creative solutions nobody programmed explicitly.
  • Adapts to the environment — a dynamic policy, not a frozen rule set.
  • Handles sequential trade-offs — it plans several steps ahead using γ.
# 8. Disadvantages

Limitations

  • Expensive to train — millions of interactions may be needed before performance stabilises.
  • Sample inefficient — every episode restarts from the same grid, unlike supervised learning.
  • Reward design is hard — a badly shaped reward produces exploitable, unintended behaviour.
  • No guaranteed optimum — tabular Q-Learning converges under mild assumptions; deep variants do not.
  • Unsafe exploration — random moves are unacceptable in robotics or medicine.
  • Hyperparameter sensitivity — α, γ, ε and the decay rate interact strongly.

Reward shaping warning. Because the agent maximises whatever it is given, optimising a proxy can produce behaviour that satisfies the proxy while defeating the real goal. This is the wireheading problem, and it is the single most common failure mode in deployed RL.
# 10. Exploration vs Exploitation

The central dilemma

The agent faces an irreducible uncertainty. Exploitation means choosing the action that is known to be best, which is profitable but never discovers anything better. Exploration means trying uncertain actions, which costs reward now but may reveal a much better option later. Our agent resolves this with an ε-greedy policy:

  • With probability ε take a random action — explore.
  • Otherwise take the highest Q-value action — exploit.
  • Decay ε from {{ epsilon_start }} down to {{ epsilon_min }} so exploration is broad early and vanishes as the policy sharpens.
εt+1 = max(εmin, εt × {{ epsilon_decay }})

Keeping a small floor at εmin rather than dropping it to zero matters: it lets the agent recover if the environment changes slightly.

# 11. Q-Learning

Q-Learning: learning the value of each action

Q-Learning is the canonical off-policy, model-free, value-based algorithm and is the algorithm behind our application. It maintains a table Q(s,a) and applies the Bellman optimality update after every transition:

Q(s,a) ← Q(s,a) + α · [ r + γ · maxa' Q(s',a') − Q(s,a) ]

Because the maximum is taken over the next state while the behaviour policy is exploratory, Q-Learning learns the optimal policy even though it acts greedily only part of the time. The estimate converges to the true Q* for tabular problems given enough episodes and a decaying step size. Our grid has only 80 reachable states, so the exact tabular solution exists — but we approximate it with a linear model so the implementation scales beyond toy grids.

Reward scale matters. Reaching the target gives +100 while a normal move costs -1. This ratio is what makes the goal reachable in practice: with a smaller goal reward the discounted return of wandering can rival that of arriving, and the agent fails to converge.
# 12. Q Function

The Q function

Q(s,a) is the expected discounted return obtained by acting a in state s and following the optimal policy afterwards:

Q*(s,a) = E [ r + γ · r' + γ2 · r'' + ... ]

Two properties make it useful. It is action-specific, so it can rank the four moves from a cell, and it is recursive, because the value of moving somewhere is defined in terms of the value of what is reachable from there. Once Q is accurate, the policy is simply π(s) = argmaxa Q(s,a).

In the RL Application page the agent's learned Q table is printed in full, one row per reachable cell, with the four action values and the greedy choice highlighted.

# 13. Epsilon

Exploration rate

ε ∈ [0,1] is the probability of acting randomly. The extremes are both useless: ε = 1 never exploits, while ε = 0 never discovers the better route and can lock the agent into a poor local optimum — it will bounce between two cells forever if those happen to be the initial best.

Our schedule starts at {{ epsilon_start }} — pure random exploration, so the agent sees the whole grid — and decays geometrically by {{ epsilon_decay }} per episode until it reaches the floor of {{ epsilon_min }}.

# 14. Gamma

Discount factor

γ ∈ [0,1] weighs immediate reward against future reward. γ = 0 makes the agent purely myopic; values close to 1 make it far-sighted and willing to accept short-term pain for a better eventual route. Our application uses γ = {{ gamma }}, which balances the two on a grid of this size.

With γ = 0.95 a reward received 10 steps ahead is still worth 0.9510 ≈ 0.60 of its face value, so long detours remain attractive as long as they are genuinely safer.
# 15. Alpha

Learning rate

α controls how much of each new estimate is absorbed: large values adapt quickly but oscillate around the true value, small values are stable but slow. We use a constant α = {{ learning_rate }}, which is appropriate because we average over hundreds of episodes rather than doing a single online fit.

In this project α is the eta0 of the SGDRegressor that implements the update.

# 16. Episode

Episodes and termination

An episode is one complete run from the starting cell until termination. On our grid an episode ends when the agent either reaches the target (a terminal state, treated as absorbing with zero future value) or exhausts the step budget of {{ max_steps }} moves. Without a step cap an exploratory agent could wander forever.

  • Start state A, reset at the beginning of every episode.
  • Terminal state T; the target is absorbing, so no update looks past it.
  • Truncation at {{ max_steps }} steps, counted as a timeout rather than a real end.
  • {{ episodes }} episodes per training run, enough for the Q-values to stabilise.

# 18. State

State representation

A state is everything the agent needs to decide its next move. Our environment is fully observable and memoryless: knowing the current cell tells the agent everything, and the Markov property holds, so state = position.

state = (row, column)   →   s = row × 10 + column   →   0 ≤ s < 100

Two states are excluded from learning: the 20 wall cells, which are unreachable and therefore have no meaningful value. That leaves 80 states and, with four actions each, a table of 320 Q-values.

In our implementation each (state, action) pair is encoded as a one-hot vector of length 400, and Q(s,a) is the model's output for that vector. This keeps the mapping general: it is exactly a tabular Q-table expressed as a linear model, which is the standard way to extend Q-Learning to state spaces too large to store.

# 19. Action

Action space

The action space is discrete and fixed: four moves are available from every cell, with no rotation or variable length. Invalid actions are still offered to the agent rather than filtered out, so it must learn that bumping into walls is costly. This keeps the environment Markovian; removing illegal moves would leak information the agent should have to discover.
