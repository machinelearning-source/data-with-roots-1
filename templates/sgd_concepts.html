SGD Classifier Concepts

Stochastic Gradient Descent applied to classification — the algorithm assigned to our group.

# 1. Name and Definition

What is the SGD Classifier?

The SGD Classifier (sklearn.linear_model.SGDClassifier) is a linear classifiers suite trained by Stochastic Gradient Descent. Instead of using the whole dataset at each step (like classic gradient descent), SGD updates the model weights using one random sample (or a small mini-batch) at a time, which makes it extremely fast and scalable to large datasets.

In this project it uses a log-loss objective (equivalent to Logistic Regression) inside a pipeline with StandardScaler, since SGD is sensitive to feature scaling.

# 2. How It Works

Algorithm Process

  1. The features are standardized (mean 0, standard deviation 1) with StandardScaler.
  2. The model starts with random weights and visits the training examples one by one.
  3. At each example it computes the gradient of the loss and updates the weights in the opposite direction (descent).
  4. The process repeats for many epochs until the loss converges.
w = w - learning_rate · ∇loss(w, sample)
# 3. Problems It Can Solve

Types of Problems

  • Binary classification (this project: credit risk).
  • Multiclass classification (one-vs-all).
  • Large-scale problems with millions of rows.
  • Online / streaming learning.
# 4. Main Characteristics

Characteristics

  • Very efficient: O(n) cost per epoch.
  • Requires feature scaling to converge faster.
  • Supports L1/L2 regularization and early stopping.
  • Has a learning rate parameter that controls step size.
# 5. Advantages

Advantages

  • Very fast training even with huge datasets.
  • Low memory usage (one sample per update).
  • Flexible: multiple loss functions (hinge, log, squared_error).
  • Good for online learning / data streams.
# 6. Limitations

Limitations

  • Sensitive to feature scaling.
  • Learning rate must be tuned manually.
  • Only linear decision boundaries (unless combined with kernels).
  • Results may vary with random initializations; needs random_state.
# 7. Real-World Example

Example of a Real-World Classification Problem

Credit risk assessment in banking. A bank must decide, from each loan applicant's features (income, requested amount, credit score, employment history), whether the applicant is a High Risk or Low Risk borrower. Millions of applications make SGD ideal because it trains quickly and can be updated as new applications arrive. This is exactly the problem implemented in the Application page.
